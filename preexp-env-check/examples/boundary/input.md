# ? 边界样例：必需输入缺失（SSH 配置未给）

## 输入（用户请求 + 环境）

**用户请求**：
> 帮我检查一下服务器环境能不能跑实验

**SSH 环境**：
- ❌ PEEC_SSH_HOST 未设置
- ❌ PEEC_SSH_USER 未设置
- （用户只说了请求，没给服务器连接信息）

## 可判定预期

Agent 触发本 Skill，在「确认输入」步骤发现 SSH 连接信息缺失：
- **不臆测**服务器地址，不随便挑一台机器去连（slide7：不把歧义悄悄吞掉）
- **向用户澄清**：「请提供服务器 SSH 连接信息（主机/用户/密钥），或设置 PEEC_SSH_* 环境变量」
- 暂停检查，等用户补全输入后继续

## 证明

证明 Skill 不会把歧义悄悄吞掉：输入不完整时主动澄清而非盲目执行。
对应 slide7「边界样例：非关键字段未知/状态不完整 → 澄清或告警」。

## 备选边界场景

- 用户给了 SSH 信息但没说用哪张 NPU → 用默认 NPU=4 并在报告中标注「使用默认 NPU=4，如需改请设 PEEC_NPU」
- ASCEND_RT_VISIBLE_DEVICES 设成了 `4,5,6`（少一张卡）→ npu_mismatch，停止报告（此场景归入 failure）
